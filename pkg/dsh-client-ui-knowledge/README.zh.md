# @deepseek-ai/dsh-client-ui-knowledge

[English](README.md) | 中文

资料库设置分区：基于 knowledge wire 域的文档库表格——上传、删除。插件通过 `ctx.slots.inject` 等待 settings 包的 `settings.section` slot，随后注册该分区（order 25）并挂载其控制器、组件、文案词典以及断线重连后的重新拉取。检索本身在模型侧完成——pre-step 召回注入与 `knowledge` 工具——从不在页面渲染：这个页面的全部职责是把文件移入移出宿主资料库。

## 分区控制器

`KnowledgeSectionController` 不持有任何自有资料库状态：每次变更都写穿 `knowledge.list`/`ingest`/`remove`，随后页面重新读取——因为模型自己的 knowledge 工具可能在两次渲染之间修改同一资料库，而 wire 上没有任何事件播报这一点。空资料库是合法的首跑状态而非失败。上传逐文件发请求，并在各自的行上报各自的结果——`reading` 聚合字节，`sending` 传输字节，终态则说明宿主的处理：已加入、带原因跳过或被拒绝——因为 store 本来就顺序摄入，而逐文件报告正是页面要展示的。只要有一个文件落地就重新读取资料库；全部未落地的批次不欠一次刷新。上传字节按受限大小的分块编码为规范 base64（对多兆文件的字节做单次 spread 会超出参数上限）。

## 渲染

资料库渲染为表格——文档标题与文件名、格式徽标、分块数、本地化的更新时间——每行一个先确认再执行的删除，共用模态框。选择器保持在可访问树中（可聚焦、有标签）而非 `hidden`，每次选择后重新清空，因此再次选择同一文件仍会上传。上传报告对终态拒绝做播报（`role="alert"`），在读取失败页上保留原位，且只有批次结束才提供关闭。整页读取失败以错误与重试取代页面；单个变更失败渲染在工作列表旁边。

## 模型体验

无，该插件只管理资料库成员关系，不贡献模型可见输入；检索在同一资料库上由模型侧完成。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **不支持并发批次** — 一个批次进行中时再次上传会被忽略，因为两者会争用同一报告位。
- **表格不做实时刷新** — 模型 `knowledge` 工具增删的条目要等分区自己的下一次重读才会出现。
- **无上传取消与进度** — 每个文件只报告阶段，不报字节数。

**运行时不变式：** 不发布伴生入口。这是浏览器端设置界面，node half 不持有事件流或可变运行时数据；资料库及其检索流水线是 Host 契约，由宿主插件和 knowledge wire 覆盖。
